# 03 — Модель мира: сетка, размещение, извлечение графа

## Сетка — `core/grid.ts`

- Мир «бесконечный», целые координаты, могут быть отрицательными. Занятость: `Map<string, string>` c ключом `"x,y"` → entityId.
- `footprintTiles(entity): Vec[]` — тайлы сущности с учётом поворота.
- Размеры и порты (при dir = 0, «смотрит вверх», w×h в тайлах). Стороны в локальной системе станка: FRONT — куда указывает `dir`, BACK — противоположная, LEFT/RIGHT — если смотреть по `dir`:

| kind | size | входы | выходы (branch) |
|---|---|---|---|
| belt | 1×1 | любая сторона | FRONT |
| miner | 2×2 | — | FRONT, оба тайла (`out`) |
| furnace | 2×2 | BACK | FRONT (`out`) |
| assembler | 3×3 | BACK | FRONT (`out`) |
| splitter | 2×1 | BACK, оба тайла | FRONT левого тайла = `true`, правого = `false` |
| mixer | 3×3 | BACK + LEFT + RIGHT (все тайлы этих сторон) | FRONT, центральный тайл (`out`) |
| chest | 1×1 | BACK + LEFT + RIGHT | FRONT (`out`) |
| lab | 2×2 | BACK, оба нижних тайла | FRONT левого верхнего = `pass`, правого верхнего = `rework` |
| silo | 3×3 | BACK, все тайлы | — |
| telegram | 2×2 | BACK, оба тайла | — |
| accumulator | 2×2 | — | — |
| manipulator | 1×1 | ДВА разных механизма (см. ниже) | FRONT (`out`), без изменения данных |

`accumulator` (усиление) — энергослой: занимает тайлы, но портов не имеет и в трассировке лент не участвует, `buildGraph` его игнорирует. Запитанность станков считается отдельно (docs/04).

`lab` — футпринт исправлен на 2×2 (был 2×1): прямоугольник 2×1 при `dir=1/3` занимал 1×2 (высокая узкая клетка вместо широкой), из-за чего станок «криво растягивался» при повороте вместо стабильного квадратного футпринта. Порты (`pass`/`rework` на FRONT, вход на BACK) считаются той же логикой, что и раньше (FRONT — локальный ряд `dy=-1`, BACK — нижний ряд футпринта, `rotOffset` с `baseSize.w/h`) — только `baseSize.h` теперь 2 вместо 1. При `dir=0` координаты FRONT-портов не изменились, а BACK-ряд входа сдвинулся на один тайл вниз (по-прежнему один ряд из двух тайлов, теперь на `y=1` вместо `y=0` — старый верхний ряд больше не вход). При `dir=1/2/3` сдвигаются уже и порты, и BACK-тайлы вместе с новым квадратным футпринтом (иначе и не могло быть — сам смысл фикса в том, что при повороте станок больше не превращается в узкую 1×2 клетку). См. проверки в `__checks__/grid.ts`.

**Вход манипулятора — это ДВА разных механизма, не один:**
1. **Терминальный (через `inTiles()`)** — `inTiles(manipulator)` возвращает **только тайл самой сущности** (`{pos}`), одинаково при любом `dir` (`rotOffset(0,0,1,1,dir)` = `(0,0)` для всех 4 направлений). Значит если лента упирается ПРЯМО в манипулятор (её `DELTA[dir]`-шаг приземляется на тайл манипулятора) — связь образуется с ЛЮБОЙ стороны, сторона физически номинальна при 1×1 footprint. Это старый, изначальный механизм.
2. **Боковой tap (через `manipulatorIntake`, новый механизм)** — направленный, конкретный тайл `manipulator.pos - DELTA[manipulator.dir]` (именно BACK-сторона, не любой сосед). Позволяет манипулятору забрать предмет из ЛЮБОГО тайла ленты, мимо которого он стоит, даже если лента продолжается дальше мимо него (mid-line grab, а не только терминальный тайл).

`trace()` (ниже) всегда предпочитает (1), если применимо — терминальная связь никогда не перехватывается боковым tap-ом (2) того же тайла.

**`manipulator` обязателен для любой передачи станок↔станок.** Прямое соединение
двух «настоящих» станков — впритык или через одни ленты, без манипулятора хотя бы
на одном конце связи — **не образует Edge**: `trace()` (ниже) намеренно блокирует
такой случай. Это касается и связки лента→станок/станок→лента, не только
станок↔станок напрямую: манипулятор нужен на КАЖДОЙ границе «лента или пустота» ↔
«станок». Единственное исключение — belt↔belt (лента передаёт ленте без манипулятора,
это просто конвейер).

- Хелпер поворота смещения внутри footprint (для тайлов и портов):

```ts
// локальное смещение (0..w-1, 0..h-1) → мировое смещение от pos
function rotOffset(dx: number, dy: number, w: number, h: number, dir: Dir): Vec
// dir=0: (dx,dy)  dir=1: (h-1-dy, dx)  dir=2: (w-1-dx, h-1-dy)  dir=3: (dy, w-1-dx)
```

- `outPorts(entity): { tile: Vec; branch: Branch }[]` — тайлы **снаружи** footprint у выходной стороны; `inTiles(entity): Set<"x,y">` — тайлы footprint, принимающие вход.

## UX размещения — `game/input.ts` (использует grid/store)

- Hotbar (клавиши 1..9 или клик) выбирает `selectedTool`.
- **Ghost**: полупрозрачный спрайт следует за мышью с привязкой к сетке; зелёный tint — все тайлы footprint свободны, красный — нельзя.
- ЛКМ — поставить. **Drag ЛКМ для ленты**: путь мыши растеризуется по тайлам (шаги по 4 направлениям, сперва по оси большего смещения), направление ленты = направление шага; существующая лента перезаписывается.
- `R` — повернуть ghost (или выделенный станок при пустом инструменте). ПКМ / `Delete` — снести под курсором. `Esc` — сброс инструмента/выделения.
- Клик по станку без инструмента → `selectedEntityId` (ConfigPanel).
- При `running` изменения запрещены — тост «Останови фабрику» (docs/01).

## Извлечение графа — `core/graph.ts`

`buildGraph(entities: Record<string, Entity>): Edge[]`

```
для каждого станка m (kind != 'belt'):
  для каждого порта { tile, branch } из outPorts(m):
    trace(tile, fromManipulator = m.kind === 'manipulator') → { to, path }
    если path непуст или to найден → Edge { id: `${m.id}:${branch}:${n}`, from: m.id, branch, to, path }

trace(start, fromManipulator, manipulatorIntake):
  path = []; cur = start; visited = Set
  пока grid[cur] — belt:
    path.push(cur); visited.add(cur)
    forward = cur + DELTA[belt.dir]
    // приоритет терминала: если forward — манипулятор, которому этот тайл и так
    // валиден как вход (обычный «лента упирается прямо в манипулятор» случай) —
    // боковой tap НЕ применяется, трасса идёт дальше и попадёт на него нормально
    если НЕ (grid[forward] — манипулятор И "x,y"(forward) ∈ inTiles(манипулятор)):
      если manipulatorIntake[cur] существует → { to: manipulatorIntake[cur], path }  // боковой tap мид-лайн тайла
    cur = forward
    guard: cur ∈ visited или path.length > 500 → break        // кольцо лент
  если grid[cur] — станок и "x,y" ∈ inTiles(станка):
    если fromManipulator ИЛИ станок.kind === 'manipulator' → { to: станок.id, path }  // манипулятор с любой стороны
    иначе → { to: null, path }                                  // два «настоящих» станка без манипулятора — тупик
  иначе → { to: null, path }                                    // тупик (порт в пустоту)
```

- `manipulatorIntake: Map<"x,y", manipulatorId>` строится один раз на `buildGraph` из ВСЕХ манипуляторов карты: ключ — тайл `manipulator.pos - DELTA[manipulator.dir]` (единственный, направленный BACK-тайл этого манипулятора, не «любой сосед»). Манипулятор перехватывает предмет с ЛЮБОГО тайла ленты, мимо которого стоит — не только с терминального (mid-line grab), но с приоритетом: если лента упирается прямо в манипулятор (терминальный случай), боковой tap соседнего манипулятора игнорируется — терминальная связь никогда не крадётся сбоку.
- **Первый tap по ходу трассы забирает ВЕСЬ поток с этого источника.** Если после точки перехвата лента идёт дальше к другому манипулятору/станку — туда уже ничего не долетает (единственная трасса от source обрывается на первом tap). Если два источника сливаются в одну ленту ДО точки tap — оба landят на этом же манипуляторе (обе трассы независимо доходят до одной и той же точки). Это MVP-упрощение: разделения потока по «полосам» ленты нет, `trace()` — один путь на один output-порт.
- 1×1 манипуляторы не перекрываются (`canPlace`), но МОГУТ легально делить один и тот же intake-тайл (стоять с разных сторон одной ленты) — при коллизии в `manipulatorIntake` детерминированно побеждает манипулятор с лексикографически меньшим `id`, независимо от порядка `Object.values(entities)` (порядок может меняться после save/load, вставки/удаления сущностей) — `buildGraph` обязан быть чистой функцией геометрии мира.
- Манипулятор с `m -> m` self-edge (лента на его FRONT-тайле ведёт обратно на его же вход) — это НЕ новое поведение этого фикса: такие self-edges были возможны и раньше (терминальный механизм через `inTiles()` не требует новой tap-логики, воспроизводится и на коммите до этого фикса). Не зависание — ограничено `ttl: 64`, как и любая другая петля, — но форма edge, о которой стоит помнить при отладке.
- **Приоритет терминала — это lookahead ровно на один тайл вперёд.** Он защищает только связь «tap-тайл ↔ манипулятор на СЛЕДУЮЩЕМ тайле». Цепочка вида лента→лента(tap M2)→лента→манипулятор M1(терминал) на расстоянии двух и более тайлов ничем не защищена: M2 всё равно перехватит весь поток раньше, чем трасса дойдёт до M1, и это тот же класс проблемы, что и исходный ревью-блокер, просто на шаг дальше. Это осознанно НЕ исправляется (см. пункт выше про «первый tap забирает весь поток») — терминальные связи защищены только от tap-а НА своём же intake-тайле, а не в целом по всей трассе.
- **Слияние лент** получается само: трассы разных станков проходят по общим тайлам, пути независимы.
- Порт без ленты вовсе (path пуст, to null) → edge не создаётся; пакеты с этого выхода дропаются сразу (`dead-end`).
- Несколько edges с одного branch (например, miner 2×2 с двумя лентами) → пакет клонируется на каждый.
- **Петля критика** (lab `rework` → назад в assembler) — это нормальный Edge через манипулятор; от вечных кругов защищает `ttl` (docs/04).
- Пересборка: полный `buildGraph` на каждое изменение поля (сотни сущностей — O(n·длина трасс), достаточно).
- Практическое следствие: каждая связка «станок → (ленты) → станок» на карте — это ДВА Edge (станок→манипулятор, манипулятор→станок), а не один. У манипулятора в `graph.ts` есть своя логика (`manipulatorIntake`, приоритет терминала) — это НЕ обычный станок в общем цикле, `trace()` явно знает про manipulator.

## Чертежи (усиление, реализовано — E4)

Инструмент выделения области (клавиша `B`, `core/blueprint.ts` + `game/input.ts`): рамка → сущности, чей **весь** footprint внутри рамки (частично задетые краем не попадают), сериализуются с координатами относительно bounding box → список чертежей в localStorage (`ncf.blueprints.v1`) + экспорт строкой (base64 JSON, UTF-8-safe) для шеринга. Постановка чертежа = групповой ghost, `stampBlueprintId` не сбрасывается после клика — чертёж остаётся «на кисти» для повторной постановки, как обычный инструмент.

## Задачи и acceptance criteria

- B1: `types.ts`, `grid.ts` (footprint, rotOffset, порты, занятость), `__checks__/grid.ts`. AC: asserts на rotOffset для всех 4 dir; footprint сплиттера при dir=1 занимает 1×2; порты splitter дают `true` слева; mixer имеет входы с трёх сторон.
- B2: `graph.ts`, `__checks__/graph.ts`. AC: мир «miner → 2 ленты → манипулятор → assembler» даёт 2 edge (miner→манипулятор, манипулятор→assembler); лента в никуда → `to: null`; кольцо лент не подвешивает trace; lab-петля через манипулятор образует корректный Edge назад; два станка впритык без манипулятора → 0 edges.
- A3: input + ghost + hotbar (совместно с docs/06). AC: цепочка «шахта → 5 лент → станок → лента → ракета» собирается мышью за минуту; R и снос работают.
