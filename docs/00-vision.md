# 00 — Видение

## Идея одной строкой

Игрок строит **фабрику по обработке информации**: ставит станки (AI-агенты и обработчики), соединяет их конвейерами, и по лентам в реальном времени едут предметы — куски данных, которые превращаются во что-то новое, проходя через станки. То, что в n8n — невидимый JSON по клику «Execute», здесь — физический процесс, который видно глазами.

## Предмет на ленте

Предмет — единица данных в моменте пайплайна. У предмета есть:

- **Тип/иконка**: текст — лист 📄, структура/JSON — шестерёнка ⚙️, картинка/медиа (URL) — фото 🖼, вердикт критика — флажок 🚩, пачка из склада — ящик 📦, ошибка — лом 🔩.
- **Видимый размер**: большой документ — крупный предмет, короткая фраза — мелкий (чисто визуально, по длине payload).

Содержимое с ленты не читается — виден процесс и превращение. Реальный текст/JSON — по клику на станок или предмет (панель).

## Станки (маппинг Factorio → пайплайн)

| Станок | kind | Роль | Что делает |
|---|---|---|---|
| Шахта | `miner` | Input | Вбрасывает сырьё: заданный текст, содержимое URL или входящий вебхук (POST снаружи). Не обрабатывает. |
| Печь | `furnace` | Препроцессор | Дешёвая обработка **без LLM** (JS): почистить текст, разбить на куски, отформатировать. Быстро, «не думает». |
| Сборочный станок | `assembler` | **Агент — сердце системы** | Вход + «рецепт» (системный промпт/роль) → реальный вызов LLM → новый предмет. Рецепты: суммаризатор, переводчик, классификатор, критик, генератор… Выбор рецепта = выбор продукции станка в Factorio. |
| Разветвитель | `splitter` | Маршрутизатор | Направляет предмет на одну из двух лент: по условию-выражению или спрашивая мини-LLM. |
| Химзавод | `mixer` | Объединитель | **Ждёт по ингредиенту с каждой входящей ленты**, соединяет в один новый предмет (склейка или LLM-синтез: «кратко» + «перевод» → финальный пост; мнения агентов → решение). |
| Сундук | `chest` | Буфер/Память | Копит предметы до `batchSize`, затем выпускает пачку (batch-обработка дальше по цепочке). |
| Лаборатория | `lab` | Критик | Проверяет качество предмета (LLM по критериям) → ветка `pass` дальше или `rework` обратно на доработку — петля «агент написал → критик проверил → агент переписал». |
| Ракета | `silo` | Output/Финиш | Конечная точка: предмет доехал → запуск ракеты → панель с финальным результатом. Кульминация демо. |
| Антенна | `telegram` | Внешняя отправка | Терминал: шлёт результат в Telegram — фабрика дотягивается до реального мира. |

## Лента — механика, не провод

- **Затор**: агент «думает» (реальный LLM-вызов, секунды) — предметы физически скапливаются перед станком. Bottleneck пайплайна виден глазами, без графиков и логов. Это главный честный аргумент «почему игра, а не блок-схема».
- **Слияние**: параллельные агенты сходятся лентами в смеситель — видно, как один ингредиент ждёт второго.
- Скорость лент в MVP одна (400 мс/тайл); «быстрые ленты» — в усилении.

## Модули: MCP-инструменты как апгрейды станков

В Factorio в станок вставляют модули (скорость/продуктивность), меняющие его работу без смены рецепта. Здесь модуль = **подключённый MCP-инструмент**: агент может вызвать его посреди хода, не меняя основной рецепт. Слоты (1–3) есть только у станков, которые «думают»: **assembler** и опционально **lab**.

- Примеры модулей: **веб-поиск** (агент ищет в интернете посреди обработки), **память** (агент заглядывает в станок-Склад как в RAG-хранилище); идеи дальше — файлы, БД, браузер.
- Модуль не бесплатен: каждый вставленный модуль повышает потребление энергии станком — tool call это реальные дополнительные токены/время. Ровно как модуль скорости в Factorio повышает энергопотребление.
- Питч-угол: «мы не просто нарисовали ленты — мы честно смэппили открытый стандарт MCP на систему модулей Factorio».

## Ядро vs усиление

**Ядро (без этого не демо):** `miner → assembler → splitter → mixer → silo` + антенна-telegram и шахта-вебхук, ленты с движущимися предметами, затор у занятого станка, запуск ракеты с панелью результата. Ракета — в ядре: дёшево, а вау-эффект максимальный.

**Усиление (в порядке отдачи на минуту работы):**

1. **Электричество** — один ресурс, и это на самом деле **токены LLM**. **Аккумулятор** хранит заряд и показывает уровень (= лимит токенов на прогон), станки тратят его на работу; нет заряда — станок мигает «нет питания» и стоит, предметы ждут. Кнопка «Зарядить» = поднять лимит.
2. **Модули** — хотя бы один реальный MCP-модуль (веб-поиск), чтобы показать вживую, а не на словах.
3. `furnace` (препроцессор), `chest` (буфер/память), `lab` (критик-петля).
4. **Энергостолбы** — красивый визуал: от аккумуляторной станции тянем столбами ЛЭП до станков, провода рисуются сами; станок вне линии обесточен. **Чертежи** — сохранить кусок фабрики, переиспользовать, поделиться строкой-экспортом. Самое красивое и самое дорогое — только если всё предыдущее стабильно.

Энергетический слой объясняет жюри реальную экономику LLM-агентов на глаз: уровень заряда аккумулятора = остаток токен-бюджета.

**Анти-скоуп:** обработка изображений моделями (предмет-«картинка» — только иконка для URL/файла), электросеть-провода, враги, исследования, подземные ленты, undo/redo, мобильная версия, мультиплеер. Ассеты Factorio не используем (копирайт Wube) — спрайты свои.

## Демо-сценарий (3 минуты)

1. **0:00** Пустое поле. «Это фабрика по обработке информации». Ставим шахту, вписываем текст статьи.
2. **0:30** Две ленты от шахты к двум сборочным станкам: рецепты «Суммаризатор» и «Переводчик» из выпадашки.
3. **1:00** Обе ленты сходятся в химзавод (режим LLM: «объедини в короткий пост с переводом»), от него лента в ракету.
4. **1:30** **Run.** Предмет клонируется на обе ветки, станки думают (жёлтые лампы), у медленного копится очередь — «вот bottleneck, глазами». Смеситель держит первый ингредиент у входа, ждёт второй.
5. **2:10** Оба готовы → смеситель соединяет → предмет едет в ракету → **запуск** → панель с финальным текстом.
6. **2:30** Включаем у шахты интервал 3 с — конвейер живёт сам, очереди дышат. Вторая фабрика (Load demo): шахта-вебхук принимает `curl` с отзывом, сплиттер-LLM решает позитив/негатив, негатив улетает антенной в Telegram — телефон пикает в зале.
7. **2:50** Финал: «Видимые данные = наглядная отладка. Автоматизация с порогом входа компьютерной игры».

**Fallback:** кнопка Load demo (`web/public/demo.json`) — собранная фабрика; сервер без ключа отвечает LLM-моками с задержкой 1.5 с — демо не зависит от Wi-Fi и API. Репетировать оба варианта.
