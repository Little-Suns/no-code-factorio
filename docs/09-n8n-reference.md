# 09 — Референс n8n: что именно мы воссоздаём

n8n — только образец. **Агентам не нужно открывать репозиторий n8n-io/n8n** — всё, что мы берём из него, выписано здесь; остальное сознательно не берём. Если чего-то нет в этом доке — значит, оно нам не нужно.

## Модель воркфлоу n8n → наша модель

| Концепт n8n | Как устроен в n8n | Наш аналог | Где описано |
|---|---|---|---|
| Workflow | `{ nodes: [...], connections: {...} }` — граф нод | мир фабрики → `buildGraph` → `Edge[]` | docs/03 |
| Node | `type` + `parameters` (конфиг) + позиция на канвасе | `Entity { kind, config, pos, dir }` + `NodeDef` | docs/01, 05 |
| Connection | выходы нод индексированы: `main[0]`, `main[1]`… | `Edge.branch`: `out` / `true` / `false` / `pass` / `rework` | docs/01, 03 |
| Item | единица данных между нодами: `{ json: {...} }`; ноды обрабатывают массив items | `Packet { data }` — **один пакет = один item**; пачка (batch из chest) = item с массивом внутри | docs/01, 04 |
| Trigger-ноды | отдельный класс нод без входа: Manual, Schedule, Webhook | `miner` c режимами text (кнопка ▶), cron (интервал), webhook | docs/05, 04 |
| Webhook Trigger | n8n поднимает URL, POST на него запускает воркфлоу | `POST /webhook/{nodeId}` на нашем сервере → SSE → пакет из шахты | docs/07, 04 |
| Expressions | `{{ $json.field }}` в любом текстовом параметре | `tpl('{{path.to.field}}', data)` — упрощённая версия без `$json`-префикса | docs/04 |
| IF node | одно условие → два выхода (true/false) | `splitter` (branch `true`/`false`); LLM-режим — наше расширение | docs/05 |
| Merge node | режимы append (поток) и combine (ждать пары со всех входов) | append = физическое слияние лент; combine = `mixer` (ждёт по ингредиенту с каждой входящей ленты) | docs/03, 04 |
| Code node | пользовательский JS: `items` → return items | `furnace`: `new Function('data', code)` над одним item | docs/05 |
| HTTP Request node | универсальный запрос с шаблонами в url/body | режим URL у шахты + `proxyFetch` в NodeCtx | docs/05, 07 |
| AI/LLM-ноды | цепочки агентов, модели, инструменты | `assembler` (рецепт = system prompt) + модули-MCP | docs/05 |
| Статус исполнения ноды | иконки running/success/error на канвасе, у ноды видны последний вход/выход | `node-status` + лампа на станке; `lastIn`/`lastOut` в ConfigPanel | docs/04, 06 |
| Ошибка ноды | стоп ветки или continue-on-fail | всегда «continue»: пакет → лом + дым, фабрика живёт | docs/04 |
| Execute workflow | ручной прогон: batch данных проходит целиком | у нас **непрерывный поток** (Run/Stop) — сознательное отличие и фича | docs/04 |
| Шаблоны воркфлоу | галерея готовых шаблонов | чертежи (усиление E4) + `demo.json` | docs/03, 08 |

## Формы конфигурации нод

В n8n у каждой ноды декларативная схема параметров (`properties: [{ displayName, name, type, default }]`), по ней рендерится панель. Мы воссоздаём это как `NodeDef.schema: Field[]` → `FormRenderer` (docs/05, 06). Никакого динамического «displayOptions/зависимых полей» из n8n не берём — плоский список полей.

## Что сознательно НЕ воссоздаём

- **Credentials-система** (шифрованное хранилище, OAuth-флоу) — ключи живут в env сервера и config станков.
- **Массив items на связи** — у нас один пакет = один item; батчинг делает `chest`.
- **Sub-workflows, error-workflows, версии нод, pinned data, binary data** — вне скоупа.
- **Очереди исполнения / workers / масштабирование** — движок в браузере (docs/04).
- **Канвас-редактор n8n** (Vue Flow, свободные координаты, провода-кривые) — у нас тайловая сетка и ленты, это и есть продукт.
- **Код n8n** — не копируем ничего: лицензия Sustainable Use License, да и стек другой.
